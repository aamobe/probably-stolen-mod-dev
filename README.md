# 深空当铺专用模板

配套入口是 [AGENTS](AGENTS.md) 和 [总方案](总方案.md)。本套面向正式版官方 Mod，尚未绑定具体 Mod；接口是官方文档依据，未对本机程序集编译或实测。

| 当前问题 | 最短入口 |
| --- | --- |
| 我想做某项功能，用什么接口？ | [接口速查](docs/接口速查.md) |
| 已知道方法名，在哪查示例？ | [接口符号索引](docs/接口符号索引.md) |
| 何时调用、如何清理、读档会怎样？ | [接口开发卡](docs/接口开发卡.md) |
| 需要完整参数示例和限制 | [官方接口章节目录](docs/官方接口/目录.md) |
| 从哪里来、适用于哪个版本？ | [来源与适配](docs/来源与适配.md) |

复制整个目录到项目后，按总方案“从通用模板生成项目规范”填写 Mod ID、目标游戏版本、目录和实际命令。已有项目先比较后按需吸收，不覆盖其已有规则。文档参考库不进入 Mod 发布包。

## 文档检查与更新

首次克隆后，在本目录用 PowerShell 7 下载固定版本官方资料到被 Git 忽略的本地缓存：

```powershell
pwsh -NoProfile -File scripts/Fetch-OfficialReference.ps1
```

随后执行本地检查：

```powershell
pwsh -NoProfile -File scripts/Check-Reference.ps1
```

此命令验证快照哈希、生成一致性、本地导航与锚点、接口卡依赖基线，以及已知规则残留；不编译、不部署、不启动游戏，不检查外链在线状态。

更新官方版本时：确认来源和目标游戏版本，更新 docs/官方资料 中的原始文件及 source.json 的提交、日期和哈希；读 APIChanges 并审阅差异，再运行生成器。不要仅为消除校验失败就刷新哈希。

```powershell
pwsh -NoProfile -File scripts/Build-ApiReference.ps1
pwsh -NoProfile -File scripts/Check-Reference.ps1
```

生成器维护官方章节和符号索引；人工审阅接口速查、开发卡、AGENTS 与总方案的适配是否仍成立。Check-ApiCards.ps1 会按 docs/接口卡依赖.json 列出受影响的开发卡；完成复核后才更新依赖哈希和复核提交，不得让生成器自动接受。官方新增标题可能改变编号，检查脚本会报出旧章节或断链，确认后再清理旧文件。保留源快照来源与差异记录。

## 官方资料边界

官方仓库截至本次核对未声明许可证。本仓库发布自行编写的适配说明、接口名称索引和工具；官方全文与拆分正文只保存在用户本地缓存，不随 Git 提交。导航链接指向官方固定提交。根目录许可证适用于本仓库自有内容及明确许可的通用模板改编，不授权官方文档。
