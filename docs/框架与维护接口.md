# 框架与维护接口

适用于使用官方 `IMod` 的《深空当铺》Mod。本文记录 Mod 内部的接入约定和验证方法。官方签名与示例见[接口开发卡](接口开发卡.md)和[官方接口目录](官方接口/目录.md)，实际时序以目标版本的程序集和实机行为为准。

[可编译骨架](../framework/README.md)已提供运行期所有权、事件租约、诊断和官方加载入口。物品注册、会话绑定和库存恢复可按下表随真实玩法接入。

## 选用模块

从第一个真实功能开始接入。先用显式装配串起入口、所有权和诊断。有第二个接入点时，再比较依赖与失败语义，决定是否共用代码。各 Mod 自行维护稳定 ID、存档键、诊断字段和业务状态。

| 模块 | 宿主依赖与生命周期 | 失败语义与最小接入 |
| --- | --- | --- |
| 运行期所有权 | 在 `IMod` 启用时装配，资源就绪后继续获取，停用时逆序释放。用官方资源事件时按 Mod ID 过滤。分别记录借用句柄、自建 Unity 对象和 Harmony 补丁的归属。 | 获取可能部分成功时，先登记释放动作。一次释放失败仍继续其他清理。只有可确认幂等和所有权的局部清理才适合重试。用一个真实监听器或资源验证启停。 |
| 事件与逐帧任务 | 订阅和更新任务返回可释放的租约，宿主负责事件触发和逐帧调用。回调持有会话代次和当前档案引用，换档后失效。 | 单个回调抛错时记录故障并按既定顺序继续。先接一个实际事件。若引入逐帧调度，测试遍历中撤回和新增任务的生效时机。 |
| 只读诊断 | 报告采集版本、资源状态、会话、模块阶段、故障和必要的业务计数，以值快照写入 `Player.log`。采集完成时复核会话，未知状态明确标注。 | 用固定模块、阶段和故障码有界聚合，日志限流与计数分开。报告读取保持无副作用。先接一个真实失败点和一个主动报告入口。若有维护专用按键或测试工具，独立构建并检查正式 DLL 的隔离。 |
| 物品定义与注册 | 资源就绪时通过官方目录注册。定义按来源检查重复键，持久 ID 与图像键分别维护。创建时核对原版实际使用的全局工厂委托及其归属。 | 遇到 ID 冲突保留现有工厂。卸载前再次核对委托，只撤回本 Mod 持有的注册。用一个真实物品验证注册、生成、保存和重读。发布后用本 Mod 的身份基线保护旧 ID 和映射。 |
| 读档完成与库存恢复 | 官方早期读档事件用于绑定当前存档。需跟踪完成时，把晚期信号与本次调用、返回结果和当前会话关联。依赖库存的功能还需核对实际解码结果。 | 读档不完整时保留待处理业务，提示保留原档，暂缓受影响的发放、消耗和修复。保留原版读写路径。排障后确认完整恢复，再执行本次修复或继续待处理业务。 |

判定本次库存恢复失败时，自动通过现有日志入口向 `Player.log` 写入一条 `[读档恢复失败]` 汇总。把同一次读档中的多项故障合并，记录受影响的库存、可识别的物品 ID 和失败原因。记录以本次读档为单位，后续提示、回调和主动查看诊断不重复写入这条汇总。排障后成功重读不产生新的失败记录。

## 验证场景

| 场景 | 自动替身或静态检查 | 目标版本实机 |
| --- | --- | --- |
| 启停、部分失败和换档 | 模拟资源延迟、获取抛错和释放抛错，核对逆序清理、剩余清理继续、旧回调失效。检查报告在换档时失效及日志限流下故障仍计数。 | 在支持的启停路径上核对回调、对象和补丁是否重复。换档后触发原有回调，核对当前档未被旧会话改动。 |
| 退回主菜单再进同档 | 模拟 Unity 对象判空但原版全局目录仍持有托管引用、重复目录被拒、工厂委托被替换。核对登记数、实际可创建状态和卸载所有权。 | 首次进档取得并保存自有物品，退出再重进同档，核对旧物品可恢复、新物品可创建。若有付款、发放或容器，检查实物和结算数量，再次重读核对无重复。另测 A/B 档隔离。 |
| 库存恢复不完整 | 覆盖单件工厂失败、原版库存拒收、容器子槽缺失、缺文件、重复或迟到的晚期事件，以及晚期事件后原版抛错。若目标版本支持同 ID 占位，核对其他物品继续恢复、只提醒一次、报告能定位问题、原版保存仍可执行。 | 使用原档副本或专用测试档分别制造失败和恢复。核对异常读档期间待处理业务保留，排障后重读且库存完整时业务只执行一次。另测纯原版档，以及项目明确支持的第三方快捷读档路径。 |
| 读档失败自动诊断 | 同一次读档制造目标库存拒收与容器子槽缺失，再触发提示路径。断言仅新增一条失败汇总，且同时列出两个问题的库存、物品 ID 和原因。排除故障后成功重读，断言新增失败汇总为零。 | 用问题档副本读档，看到提醒后退回主菜单，在本次 `Player.log` 中核对失败汇总只出现一次。排障后重读同一副本，按两次读档之间的日志位置核对恢复成功后没有追加失败汇总。 |

## 记录证据

- 记录目标游戏版本、Mod 构建身份、触发步骤、预期、实际结果和相关日志。补丁依赖的库存列表、占位语义和完成时序，随游戏版本重新核对。
- 自动替身用于验证分支与时序。编译和静态检查用于验证类型、编译产物与构建隔离。真实目录、Unity 对象、存档和其他 Mod 的交互由实机验证。
- 案例来自 CorpPresence 1.2.0 至 1.2.3。1.2.1 修复了重进后目录的 Unity 判空问题，1.2.3 补齐了单件失败和不完整恢复的暂缓策略。1.2.3 发布记录载明 29 项读档与 47 项恢复回归通过，玩家原档实机复测仍待完成。 [1.2.1 发布记录](https://github.com/aamobe/CorpPresence/blob/ee07bbb10fe69119b4188171ecfee961fc146b28/docs/releases/1.2.1.md) · [1.2.3 发布记录](https://github.com/aamobe/CorpPresence/blob/ee07bbb10fe69119b4188171ecfee961fc146b28/docs/releases/1.2.3.md)
